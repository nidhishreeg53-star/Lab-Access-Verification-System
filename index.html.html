    Time complexity and limits of using only trees

    OperationAverageWorst (skewed tree)
    Search, insert, delete researcherO(log n)O(n)
    Verify one request (search + 5 checks)O(log n)O(n)
    Dequeue next request (smallest key)O(1)O(m)
    Enqueue request (key always largest)O(m)O(m)
    Record a decision (key always largest)O(L)O(L)
    Traversals (inorder, preorder, postorder)O(n)O(n)
    SpaceO(n + m + L)O(n + m + L)

    n = researchers, m = pending requests, L = log entries. A plain BST is not self-balancing: inserting sorted IDs (use the R107, R108, R109 button) turns it into a chain and every search becomes O(n). Request and log keys only ever increase, so those two trees are always chains and a queue or list does the same job with less work. Each node costs two child pointers, and the data is lost when the page closes.
